# repo-governance

把一个裸仓库拉到「跨会话可持续协作」的治理水平——一个供 ZCode / Claude Code 等
agent 环境使用的 skill。

一次会话把事做对不稀奇；几十个会话之后，任务状态、决策理由、文档还能对得上，
才需要治理。当你和 agent 隔着多个会话在同一个仓库里持续干活，最早腐烂的不是
代码，是「现在做到哪了」「当时为什么这么决定」「哪些方案已经否决过」。

## 它给仓库装什么

```
AGENTS.md                  协作规则唯一入口（开工必读 → 状态页 的冷启动路径）
docs/
├─ project-context.md      背景 / 术语 / 环境（事实层）
├─ project-status.md       基线 / 进行中 / 待验收 / 待办（状态层）
├─ architecture/source-map.md   分层与「改需求从哪里下手」
├─ workflow/development.md      任务闭环细则（建卡 → 实现 → 验证 → 收尾）
├─ decisions/decision-log.md    四字段决策记录（背景/决定/备选/重开条件）
└─ tasks/                       任务卡（目录即清单，终态冻结入子目录）
scripts/check-docs.mjs|.py      文档门禁（零依赖，按仓库运行时二选一）
```

## 核心设计（每条带 why，详见 [SKILL.md](SKILL.md)）

- **gate 行 = 门禁唯一权威源**：状态枚举与终态目录映射写在任务卡模板的一行机器
  注释里，`check-docs` 只认它——改文档即改门禁，规则与校验永不漂移。
- **只认命令输出，不认自述**：「完成」绑定单一总门禁命令的退出码。自述式完成是
  agent 最常见的虚报形态。
- **终态冻结 + 勘误追加**：完成/取消的卡入子目录后正文不可改；后续证伪只允许在
  文末追加勘误节。追溯靠 git 历史。
- **目录即清单**：tasks/ 不设手工索引——「做 A 时顺手维护 B」是最先失效的软约束。
- **决策四字段**：没有重开条件的否决案，要么永久绑架要么被无据翻案。
- **反沉积三件套**：同轮清理、双写消除、环境值不进文档。文档的默认命运是长胖。

## 安装

```bash
git clone git@github.com:Siiiege/repo-governance.git ~/.agents/skills/repo-governance
```

之后在任意未治理的仓库里对 agent 说「上治理」即可触发；仓库已有完整 AGENTS.md
治理时 skill 会自动退出（以仓库为准）。

改了门禁脚本后跑回归：

```bash
bash test-gate.sh   # 11 组用例 × node/python 双运行时，22 项断言
```

## 实测：三轮六仓，执行者与检测者分离

这个 skill 不是拍脑袋写的。测试方法：**干净上下文的子代理执行**（互不知晓设计
结论，只拿 skill + 仓库 + 一句用户指令），**独立会话核验**（只认门禁输出与 git
历史）；另测退出条款（对已治理仓库重发指令必须零改动退出）与冷启动（新会话只靠
仓内文档答「现在做到哪 / 为何这么决定 / 从哪下手」三问）。

| 轮次 | 仓库 | 考点 | 结果 |
| --- | --- | --- | --- |
| 1 | husky / click / SDD-Lite | JS 主路径、Python 双实现、已有任务文件体系的边界仓 | 全闭环 |
| 1 | （husky 复测） | 退出条款、冷启动三问 | 全过 |
| 2 | duf / bat | 无门禁命令的 Go 仓从零自举、无工具链的 Rust 仓、成熟仓双写消除 | 全闭环 |
| 3 | awesome | 纯文档仓、适用判定路径 | 全闭环 |

实测产出约 20 条缝隙，全部回填或明确留观——包括一次两仓独立同踩的 `git mv`
时序陷阱（定稿须先 `git add` 再 `git mv`，否则提交 2 装进旧版本）。完整记录见
[docs/evaluation.md](docs/evaluation.md)。
