# 多会话并行同仓（按需参考）

实施步骤的分支细则——本文件**留在技能内按需读，不复制进目标仓**。适用：
多个 agent 会话同时在同一仓库（甚至同一工作区）干活。治理脚手架默认假设
「跨会话接力」（上一会话收尾、下一会话冷启动接力），并行是更强的形态；
单会话 / 接力仓不需要本篇。以下经验全部来自真实并行仓的实测翻车
（来源：rsra 仓 2026-10 多会话实战，决策 D-111 及各任务卡取证）。

## 门禁侧：不拦合法中间态

- **孤儿登记只问责已进 git index 的卡**：建卡（落盘）到登记状态页之间的
  空档是并行会话的合法中间态——全仓态门禁在空档内被其他会话触发就 FAIL，
  实测会把并行收尾逼上 `--no-verify` 绕过。check-docs 已按此实现
  （未 add 的草稿卡降级为提醒）。
- **提交锚只在提交那一刻校验**：与上一条同一原则——门禁的输入不能用
  「未共享 / 提交前不可知」的状态。期限提前到落盘瞬间会拦合法中间态，
  推后到事后审计则留绕过面。提交侧的 gate 配置、任务卡与决策均从 index 读取，
  工作区未暂存的草稿不作为本笔提交的锚证据。

## 任务号撞号

同日多会话各自建卡，`T-YYYYMMDD-NN` 的 NN 会撞（实测三次：开工时对方登记
尚未入库，后觉方才发现）。处理：后觉方挪号（改卡内 ID 与文件名，状态页
登记行同步），双方卡内互相取证注明；挪号发生在提交前则零成本，已入库则
按勘误流程。开工建卡前先重查状态页与 `git status` 能降低撞号概率——但
并发窗口无法归零，不依赖它。

## 同工作区交叠文件

两会话改同一文件的不同区域时，收尾用「HEAD + 本任务改动」的内容级暂存
分离提交（按 hunks 暂存，对方行零接触，双方卡内取证）。更稳妥的并行是
各用**独立 clone + 独立分支**，交付走 git 合并——同工作区并行只是低成本的
默认形态，不是必须。

## 端口与资源

并行跑测试 / dev server / E2E 时先查端口占用（netstat），占则各自设环境变量
错开端口，并把构建产物与测试记录一并隔离到各自目录，跑完自动清理；不设
环境变量时行为与产物路径零变化（单会话不受并行基建拖累）。

## 总原则

先重查状态再动手（git status / log / 状态页以最新为准——开工时看到的登记
可能已被对方撤走）；对方先行入库的登记行、中间态文件是正常现象不是冲突；
终态收尾坚持单提交，交叠部分按上一节分离。
