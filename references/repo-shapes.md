# 摸底排查：异常仓库形态处理

实施步骤 1「摸底」的分支细则——本文件**留在技能内按需读，不复制进目标仓**。
命中哪节按哪节处理；处理结论照常写进任务卡「环境与范围」，涉及取舍的
（如 docs 目录去留）另记目标仓 decision-log。

## docs 目录冲突

`docs/`（或近名 `doc/` 等）已有既有用途——是文档站源（VitePress / Sphinx 等）
或对外分发面。三种处理先决策再动手，结论记 decision-log：

- **隔离**：文档站配置排除治理目录（如 VitePress 的 `srcExclude`）；
- **共存**：站点构建只吃自己的源目录时，治理文件与站点内容互不干扰；
- **改名消歧**：冲突目录择一改名，门禁脚本内对应路径常量同步改。

## tasks 目录占用

`docs/tasks/` 已有异用途文件（产品需求模板、团队 README 等）。处理：治理模板
改文件名避开冲突，其余异用途文件登记跳过——两个调参位是门禁脚本的
`TEMPLATE_NAME` 与 `SKIP_TOP` 常量（见 SKILL.md 调参点）。

## 无可跑检查的仓

两种命中形态：**纯文档仓**（没有代码可检查）；**本机缺编译工具链**（代码在
但跑不了 typecheck / test / build）。

- 纯文档仓：总门禁最小版就是裸 check-docs，四类验证第 1 类覆盖面如实记为
  「文档门禁」，不夸大。
- 本机缺工具链：允许显式 SKIP 段——条件执行 + 原因可见 + 状态页「待验收」
  登记 + 决策记重开条件；工具链到位后 SKIP 段必须清除。

## Makefile 死配置

载体选了仓库已有的 Makefile，但本机没有 make——Makefile 对这台机器是死配置。
处理：本机补装 make，或改用 npm script / `scripts/gate.sh` 承载总门禁。
