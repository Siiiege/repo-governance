# 分支工作流

**分支模型与提交信息约定的唯一入口**；任务闭环见 [development.md](development.md)。
总规则见根目录 AGENTS.md 的「提交纪律」。

## 分支模型（示例：main 开发 + stable 发布）

| 分支 | 用途 | 规则 |
|------|------|------|
| `main` | 开发主线 | 日常开发在此提交 |
| `stable` | 生产发布/部署主线 | 只接受从 `main` 合并，或从 hotfix 合入；**不直接在上面开发新功能** |
| `hotfix/*` | 紧急修复（一次性） | 从 `stable` 拉出，修完先回 `stable`，再回 `main`，然后删除 |

单分支仓（无发布线）把本节改写为实际模型——最简写「单分支直推」，保留
「提交信息约定」一节即可。

## Hotfix：紧急修复直接进发布版（双分支仓适用）

> **场景**：小改动要立刻进发布版，但 `main` 已开发到下一步（带着没测完的新
> 功能），不能整体合并。
>
> **核心原则：从 `stable` 拉分支改，改完先回 `stable` 发布，再回 `main` 同步。**
> 一句话记忆：绝不从 `main` 改完去合 `stable`（会带上没测的新功能）；也绝不
> 只合 `stable` 不合 `main`（修复会丢，下次合并 bug 复发）。

## 提交信息约定

Conventional Commits 前缀 + 本仓语言描述，且**必须带任务 ID（T-…）或决策锚
（D-NNN）**——接了 commit-msg 钩子的仓提交时从本笔暂存快照核对锚，合并提交豁免：

| 前缀 | 用途 |
|------|------|
| `feat:` | 新功能 |
| `fix:` | 修复 bug |
| `style:` | 样式调整（不影响逻辑） |
| `refactor:` | 重构（不改行为） |
| `docs:` | 文档 |
| `chore:` | 构建、依赖、配置等杂项 |
