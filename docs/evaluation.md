# repo-governance 实测记录

三个轮次、六个真实开源仓库的浅克隆、八个干净上下文的子代理。本文是 skill 迭代
的完整留痕：每轮发现、每条修复的对应关系、以及仍开放的观察项。

## 方法论：执行者与检测者分离

skill 的作者（或参与过其迭代的会话）亲自执行，测不出 skill 对新会话是否友好——
那是「带着答案考试」。因此：

- **执行**：每个仓库由一个全新子代理治理，只拿到 skill + 仓库路径 + 一句用户级
  指令（「使用 repo-governance skill 给这个仓库上治理」），不知晓任何评审结论。
- **核验**：主会话不插手执行，事后只认命令输出与 git 历史（门禁 PASS、上游文件
  零改动、两段式提交、工作区干净）。
- **专项**：退出条款自测（对已治理仓库重发治理指令，必须零改动退出）；冷启动
  三问（新会话只靠仓内文档回答：有无进行中任务 / 最近否决案与重开条件 / 改某类
  bug 从哪下手）。
- **负例注入**：治理收尾前故意造违规（孤儿卡、终态滞留顶层），确认门禁 FAIL
  而非摆设。

测试矩阵按三个维度选仓：运行时（JS / Python / Go / Rust / 纯文档）、既有治理
（裸仓 / 成熟仓 CONTRIBUTING+CI / 已有任务文件体系）、规模。

## 第一轮：husky / click / SDD-Lite

| 测试 | 结果 |
| --- | --- |
| husky（JS 主路径：npm scripts 复用 + CI 接线） | ✅ 全闭环 |
| click（Python：check-docs.py + pytest） | ✅ 全闭环，自发做了负例注入 |
| SDD-Lite（已有 docs/tasks 体系的边界仓） | ✅ 全闭环，产品文件零改动 |
| 退出条款自测（husky） | ✅ 零改动退出，主动拒绝顺手改 |
| 冷启动三问（click） | ✅ 三问全对、链接全通 |

P0 缝隙四条（三仓复现）及修复：

1. **`docs/` 双语义冲突**：现实仓库 `docs/` 常是 VitePress/Sphinx 站点源或分发面，
   skill 原假设它空闲 → 摸底增加用途排查，处理分支详见
   [references/repo-shapes.md](../references/repo-shapes.md)。
2. **两段式提交时序空白**：活跃态卡必须出现在提交 1（否则该提交点位孤儿检查
   FAIL）——原是执行者从门禁行为反推的隐含约束 → 明文写入 development.md。
3. **禁推克隆的 CI 死配置**：「有 CI 就挂」在永不 push 的克隆上等于永不运行的
   配置 → 区分可推送仓（挂 CI）与只读克隆（决策记录 + 待办，重开条件 = fork）。
4. **既有红**：上游自带检查项对 HEAD 零改动报错时，收进门禁等于永远红、逼人
   绕过 → 硬规则：总门禁必须当前可绿，既有红登记待办。

## 第二轮：duf / bat（P0 修复验证）

| 测试 | 结果 |
| --- | --- |
| duf（Go，无任何门禁命令，从零自举 gate.sh） | ✅ 全闭环，上游零改动 |
| bat（Rust，本机无 cargo 工具链） | ✅ 全闭环，governance 分支，既有文档零改动 |

四条 P0 修复全部验证生效。新发现 10 条，最重要的一条：

- **`git mv` 时序陷阱（两仓独立同踩、双双自愈）**：定稿编辑先落工作区再
  `git mv`，提交 2 会装进旧版本——`git mv` 只搬暂存区内容。修法入 development.md：
  **定稿先 `git add`，再 `git mv`**。两执行者独立踩同一个坑，是多代理实测独有的
  信号：单个执行者无法区分「我的失误」还是「说明书的缺口」。

其余回填：非 Node/Python 仓运行时判定（按仓库工具链）、门禁载体三选（npm script /
Makefile / gate.sh，本机无 make 时 Makefile 也是死配置）、工具链缺失时 SKIP 段
判例（显式债务：条件执行 + 原因可见 + 待验收 + 重开条件，到位后必须清除）、
`doc/` 近名目录、负例注入至少两类。

## 第三轮：awesome（纯文档仓，矩阵最后一格）

| 测试 | 结果 |
| --- | --- |
| awesome（纯 Markdown，无运行时） | ✅ 全闭环，11 文件全部新增、上游零触碰 |

历轮修复的连环确认：第三轮的执行者正确引用了「属主意图优先」「只读克隆不挂 CI」
「负例注入两类」「复验输出贴进提交 2 的 commit message」「逐字节复制未动脚本 = 免跑
回归」——前几轮写进文档的规则，后续执行者确实读到并照做了。

回填三条：纯文档仓门禁最小版 = 裸 check-docs（覆盖面如实登记，不夸大）、门禁
可绿判据的时点（从零引入时在提交 1 后演示）、任务卡 slug 约定 ASCII。

## 已知的诚实边界

- **验证层是软件形状的**：四类验证、source-map、peer 依赖影响面分析对内容仓
  不合身。内容仓一旦挂上任何 linter（markdownlint / vale / link checker），
  「只认退出码」即对内容生效。
- **约束力只及「先读 AGENTS.md 的 agent」**：这是所有 prose 治理的物理边界。
  实际约束栈：约定（harness 自动载入 AGENTS.md）→ 上下文（开工必读）→ 机器
  （门禁）→ 共享内存（git）。定位为「跨会话可持续协作」而非多 agent 并行协作
  基础设施。
- **只读克隆无外部强制**：不 push 就没有真正的外部强制，现有机制（待办 + fork
  重开条件）是文档层最优解。
- 留观项（等真实使用触发再动）：上游克隆专门适用条目、浅克隆同步策略、
  development.md 微调的更正式登记协议。

## 定位演化

初版声称「多会话 / 多 agent 可持续协作」；三轮实测后对齐为「跨会话可持续协作
+ 主会话派子代理实现 + 门禁兜底」，并据此将「待审查」态从状态机移除（六态 →
五态，审查落「审查记录」节、不占状态）。声称的与实际交付的一致，是这次迭代
最重要的收获。

## 设计变更（2026-10-16，rsra 真实使用回灌）

rsra 仓的单会话闭环任务采用单提交收尾后，卡内「提交：hash」字段自引用无解——
本提交的 hash 提交前不可知，只能事后回填，15 个提交里 6 个是单行回填（40%），
且回填违反「入目录即冻结」。据此改设计：任务↔提交的锚定为**提交信息里的任务
ID**（建卡时已有，提交那一刻锚就成立，`git log --grep=T-…` 随时可查），卡不记
hash；收尾默认单提交，两段式降为长任务的可选项；门禁新增**幽灵提交号**检查
（终态卡 ID 必须在 git log 命中）与幽灵登记对称——提交忘带任务号不再静默失联。
注意：砍 hash 的正当理由是自引用与仪式成本，**不是「双写」**——hash 是内容寻址
指针，不腐烂；按「指针也是双写」砍下去会误伤基准提交、勘误引用、依赖链接。
test-gate 回归 11 → 13 组（26 用例）全过。

## 设计变更（2026-10-16，分析子代理串行派发——事后补痕）

建卡与影响面分析可派子代理执行，主会话聚合落卡，三条核心约束：**串行不并行**
（影响面 grep 的输入是需求分析定稿的改动点，产出物正交 ≠ 执行可并行——宽 grep
只会挑噪点，方向一变全部作废重跑）；**派发前 gate**（坏输入在派发前拦下，不让
子代理白跑）；**「允许修改范围」的合成永远留在主会话**（子代理给候选不拍板，
与「审查不占状态」同一逻辑）。落位：SKILL.md 核心设计决定第 11 条、
assets/development.md「分析子代理（可选派发）」节。

本节为事后补痕：规则文本随 d4c7c2a 入库（门禁锚 `%s`→`%B` 等配套同轮），当日
本仓 code-review 审出「设计级变更未在 evaluation.md 留痕」（AGENTS.md 联动清单
要求），据此补记；设计来历细节以 development.md 节内容为准。同轮补 test-gate
用例「锚在提交正文」（标题无任务号、正文带，`%B` 下应 PASS——13 组时无用例压
住该行为），回归 13 → 14 组（28 用例）全过。

## 设计变更（2026-10-16，维护纪律改不变量式——借鉴成熟 skills 仓库）

初版 AGENTS.md（6f0a8a9）按 skill 输出骨架缩小而成，经属主三轮砍除（元解释、
开工读单、文件分工均属 no-op 或复述环境），再调研三个公开样本后定稿：
anthropics/skills 无 AGENTS.md（纯发布仓）；obra/superpowers 是贡献者护栏
（94% PR 拒绝率喂出的硬规则）；mattpocock/skills 是仓库组织不变量。定稿
形态「一段定位 + 七条提交前可核对的不变量」：地址、用例数 ×2、双实现一致、
常量与路径存在、回归 unexpected=0、出处可指认、设计变更同轮留痕。关键转变
是从习惯式表述（「数字要可回查」）到不变量式（可逐条核对的 must）。
superpowers 式贡献者护栏暂不上——伤疤未到，抄来是装样子。已识别未做：
七条中四条（地址、组数、常量、路径）可编进 test-gate.sh 机器化，先例是
mattpocock 用 `claude plugin validate --strict` 把不变量工具化。

## 设计变更（2026-10-22，rsra 回灌：提交锚改提交侧校验 + 门禁输入原则）

rsra 仓（真实使用回灌源）在 D-109 定案同日勘误：原「幽灵提交号」检查（终态卡→
git log 反查）跑在 pre-commit 时机，本笔提交未出生、log 永远滞后一笔，自引用
死结把单提交收尾机制性堵死——定案当日 6 任务被迫两段式收尾。修正为 commit-msg
钩子提交侧校验（每笔提交信息必须带真实任务 ID 或决策锚、锚必须真实存在、暂存
终态卡被本笔信息锚定、合并提交豁免）。本次回灌进 skill：门禁双实现新增
`--commit-msg` 模式、新增 assets/hooks/ 两个钩子、删全仓态 git log 反查（其
负例用例随之替换为提交侧等价用例）。

同轮回灌四项：① D-111 孤儿任务断言收窄至 git index——未 add 的草稿卡降级提醒
（并行会话建卡到登记的空档是合法中间态，全拦实测会把并行收尾逼上 --no-verify
绕过）；沉淀为设计决定 12「门禁输入不用未共享状态」。② 决策四字段机器校验
（缺背景/决定/备选、否决类缺重开条件、零条目即 FAIL；条目格式随之钉死为
`### D-NNN` + `- **字段**：` 列表行，首条决策随脚手架落地——决策锚从第一天
就可挂进提交信息）。③ 入口文档死链检查（ENTRY_DOCS 清单内文件的相对 markdown
链接断链即 FAIL，被仓库形状裁剪的文件跳过）。④ 新增 assets/branch-workflow.md
（AGENTS.md 骨架「分支模型指针」此前无落点文件）与 references/parallel-sessions.md
（多会话并行同仓的实测经验：撞号挪号、交叠文件内容级分离、端口隔离）。

test-gate 14 → 31 组（62 用例）：新增 commit-msg 套件 9 组（含伪锚前缀不误配
XD-101——ID_TOKEN / DECISION_TOKEN 加 `(?<![A-Za-z])` 边界的回归锚）、四字段
4 组、死链 2 组、D-111 2 组（已 add 拦 / 未 add 放行 / 非 git 仓 fail-closed）、
钩子端到端 3 组——钩子按运行时探测，node/python 两种门禁实现各跑一遍；
「单提交收尾过钩子」即 D-109 死结的端到端回归锚。出处：rsra decision-log
D-109 勘误（T-20261016-14）、D-111（T-20261022-07）及 project-status 并行
取证（2026-10）。

## 设计修订（2026-11-02，提交快照取证与保障边界）

评估发现安装步骤要求首条 D-1，但提交锚扫描要求至少两位数字；安装示例统一为
D-01，保留既有两位以上编号兼容性，新增按说明书首条决策提交的回归。

提交侧此前从工作区收集任务 / 决策 ID，导致未跟踪卡、未暂存的新编号也能为提交
背书。改为从 git index 读取 gate、任务卡与决策；终态卡仍核对本笔消息中的任务号。
工作区快检保持原语义。提交模式缺暂存模板或 git 取证失败即 FAIL；使用 NUL 分隔
读取暂存路径，避免 git 路径引用影响取证。新增十组回归覆盖 D-01、未跟踪任务、
未暂存任务号 / 决策、已暂存新锚、磁盘删除但 index 仍存在的锚，以及 gate 两种快照
边界。组数由 31 增至 41，双运行时共 82 项断言；结果以本轮命令输出为准。

明确 check-docs PASS 的含义：它检查结构，不证明文档语义、验收证据真实性或终态
正文冻结。任务完成还须满足验收标准与所需验证。吸收 rsra D-112：维护范围限本次
直接影响的文档，保留验收证据，替换状态基线前转移未完成事项及来源。SKILL 主文件
压缩提交锚事故细节，保留机制与原因，历史取证引用本实测记录。
